## Goal

Update the email service to:
1. Read `gift_message` from the HTTP POST JSON body (already accessible on the `data` OpenStruct).
2. Pass `gift_message` to the ERB template as a local variable.
3. Render the gift message in `confirmation.erb` conditionally, with mandatory HTML-escaping via `CGI.escapeHTML`.

The gift message text must **never** appear in any span attribute or log field.

**Prerequisite**: T-01 must be complete. This task can run in parallel with T-02.

---

## Scope

### File 1: `src/email/email_server.rb`

#### Step 1 — Add `require 'cgi'` (mandatory)

Add at the top of `email_server.rb` in the require block:

```ruby
require 'cgi'
```

`CGI` is Ruby stdlib (no gem needed) but is **not** auto-required. Without this line, `CGI.escapeHTML` in the ERB template raises `NameError: uninitialized constant CGI` at render time.

#### Step 2 — The `send_email` function signature stays the same

The current `send_email(data)` function signature takes the entire `data` OpenStruct. **Do not change the signature.** The function body already has access to `data.email` and `data.order`. The `data.gift_message` field is automatically accessible on the OpenStruct when the JSON payload includes `gift_message`.

Current signature (do not change):
```ruby
def send_email(data)
  ...
  erb(:confirmation, locals: { order: data.order })
```

Updated `erb` call (only change inside the function body):
```ruby
def send_email(data)
  ...
  erb(:confirmation, locals: { order: data.order, gift_message: data.gift_message })
```

`data.gift_message` will be `nil` when the key is absent from the JSON payload (which is the case for non-gift-wrap orders, since `gift_wrap: false` is omitted due to proto3 `omitempty`). Passing `nil` to the template is correct — the ERB guard handles it.

The call site at line 53 does NOT need to change (`send_email(data)` remains as-is).

#### Step 3 — OTel span: do NOT add gift_message

The existing handler sets `span.set_attribute('app.order.id', data.order.order_id)`. Do NOT add any attribute for `gift_message`.

#### Step 4 — Pony exception handling (error do block)

The existing `error do` block calls `record_exception(env['sinatra.error'])`, which captures `exception.type`, `exception.message`, and `exception.stacktrace` as OTLP span attributes. Do NOT modify the `error do` block.

Keep the existing behavior. Note: the email service uses Pony with `:via => :test` (no real SMTP), so the risk of mail exceptions embedding the rendered body is narrow in the test environment. The implementer should be aware that any exception message originating from the rendering path must not include the `gift_message` text.

### File 2: `src/email/views/confirmation.erb`

Add a conditional gift message section. Insert it **after `</table>` and before `</body>`**:

```erb
<% unless gift_message.nil? || gift_message.empty? %>
  <div style="margin-top: 20px; padding: 15px; border: 1px solid #e0e0e0; border-radius: 4px;">
    <h3 style="margin: 0 0 8px; font-size: 14px; color: #333;">Gift Message</h3>
    <p style="margin: 0; font-size: 14px; color: #555;"><%= CGI.escapeHTML(gift_message) %></p>
  </div>
<% end %>
```

**Critical guard order**: `nil?` must appear BEFORE `empty?` in the `||` expression. Ruby calls both methods left-to-right; if `gift_message` is `nil`, calling `.empty?` first would raise `NoMethodError`. The `||` short-circuit makes `.empty?` safe only because `nil?` is evaluated first.

**CGI escaping is mandatory** (AC-14): use `<%= CGI.escapeHTML(gift_message) %>`. Do NOT use:
- `<%= gift_message %>` (XSS risk — email body is HTML)
- `<%=h gift_message %>` (`h` is a Rails helper, not available in Sinatra)

**Type safety**: If there is any concern that `gift_message` might be a non-String type (e.g., numeric value from a malformed payload), use `CGI.escapeHTML(gift_message.to_s)` to avoid `TypeError`.

**Note on `gift_message` local variable scope**: Sinatra's `erb` with `:locals` passes values as method-local bindings. `gift_message` is accessible as a bare local variable in the template, not as `@gift_message`. This scoping is safe.

## What must NOT change

- `gift_message` must NOT be set as a span attribute.
- `gift_message` must NOT be written to the email logger or via `puts`.
- The line `puts "Order confirmation email sent to: #{data.email}"` must remain exactly as-is; do NOT add `gift_message` to it.
- The `error do` block must not be extended to log request bodies or rendered content.
- The `app.confirmation.counter` metric must not change.

## Relevant design excerpts

From [01-design.md](../01-design.md) § "Edge cases":

> ERB template must use `<%= CGI.escapeHTML(gift_message) %>` (NOT `<%=h %>` — `h` is a Rails helper not available in Sinatra). CGI is Ruby stdlib. This is a mandatory security requirement.

From [01-design.md](../01-design.md) § "Edge cases":

> `gift_message` absent from JSON payload (nil, not ""): `JSON.parse(..., object_class: OpenStruct)` returns `nil` for missing keys. The ERB guard must be: `unless gift_message.nil? || gift_message.empty?`
