## Goal

Update the order confirmation page to:

1. Display the gift wrap fee as a separate line item (when the order included gift wrap).
2. Include `giftWrapCost` in the `orderTotal` useMemo calculation so the displayed total matches the amount charged.

The confirmation page reads data from `OrderResult` (via the page's query), which now includes `giftWrap` (bool) and `giftWrapCost` (Money) after T-01/T-02 are complete.

**Prerequisite**: T-01 must be complete (TypeScript stubs updated). T-04 should be complete first (same service — avoids conflicts, and T-04's type changes may affect this file's TypeScript compilation).

---

## Scope

### File: `src/frontend/pages/cart/checkout/[orderId]/index.tsx`

#### Key architectural note: `query.order` is a string

`useRouter()` returns `query.order` as a **URL-encoded string** (not an object). The page already
JSON-parses it at approximately line 21:

```typescript
const { items, shippingCost, ...rest } = JSON.parse(
  (query.order || '{}') as string
) as IProductCheckout;
```

All gift wrap field access must use the **destructured variables**, never `query.order?.giftWrap`
— that would always be `undefined` at runtime because `query.order` is a primitive string.

#### 1. Destructure `giftWrap` and `giftWrapCost` at line 21

Extend the destructuring at the existing `JSON.parse` line to include the two new fields:

```typescript
const { items, shippingCost, giftWrap, giftWrapCost, ...rest } = JSON.parse(
  (query.order || '{}') as string
) as IProductCheckout;
```

After T-01 regeneration, `IProductCheckout` extends `OrderResult`, which will have
`giftWrap?: boolean` and `giftWrapCost?: Money`. **No manual type-definition change is needed
here** — the regenerated TypeScript stubs from T-01 add these fields to `OrderResult`, and
`IProductCheckout` extends `OrderResult`.

#### 2. Add `giftWrapCost` to the `orderTotal` useMemo

The existing `orderTotal` useMemo (lines ~23–40) uses **raw units/nanos arithmetic** — no
`CostDisplay` or similar utility function exists in this file. Match the exact same pattern.

A reference to the existing arithmetic structure (look at how `shippingCost` is added):

```typescript
const orderTotal = useMemo(() => {
  // ... existing: accumulate items.cost into total ...
  // ... existing: add shippingCost.units / shippingCost.nanos ...
  
  // Add gift wrap cost (only when present):
  const giftWrapUnits = giftWrapCost?.units ?? 0;
  const giftWrapNanos = giftWrapCost?.nanos ?? 0;
  // Add giftWrapUnits/giftWrapNanos to the running total using the same
  // units + nanos accumulation pattern already in this useMemo
  
  return /* ... the accumulated total ... */;
}, [items, shippingCost, giftWrapCost]);
```

**Critical**: Add `giftWrapCost` to the dependency array. The existing deps are `[items, shippingCost]`
— extend to `[items, shippingCost, giftWrapCost]`.

**Do NOT use a `CostDisplay(...)` function** — that function does not exist in this codebase.
Use the same `?.units ?? 0` / `?.nanos ?? 0` arithmetic pattern as the rest of the useMemo.

#### 3. Add gift wrap fee line item display

Render a gift wrap fee row alongside the shipping row, only when `giftWrap` is truthy.
Match the display component used for `shippingCost` on the same page (e.g., `<ProductPrice>`
or equivalent currency component):

```tsx
{giftWrap && giftWrapCost && (
  // Use the same row structure as the existing shippingCost row
  // Use the same currency display component as shippingCost
  <SomeRow>
    <span>Gift Wrap</span>
    <ProductPrice price={giftWrapCost} />   {/* or whatever component shippingCost uses */}
  </SomeRow>
)}
```

**Pattern rule**: Look at the existing shipping row on this page. Use the same HTML structure,
styled components, and currency display component. Do NOT introduce new styled components in
this file.

`giftWrapCost` is in the user's currency (converted by the checkout service). The existing
currency display component will handle it correctly.

#### 4. No `IProductCheckout` manual type change needed

`IProductCheckout` (likely in `src/frontend/utils/Cart.utils.ts` or similar) extends
`OrderResult`. After T-01 regenerates `src/frontend/protos/demo.ts` with `giftWrap` and
`giftWrapCost` fields, those fields become automatically available through the type inheritance.

**Do NOT manually add `gift_wrap` or `giftWrap` to `IProductCheckout`** — that would create
a duplicate definition that conflicts with the generated type.
