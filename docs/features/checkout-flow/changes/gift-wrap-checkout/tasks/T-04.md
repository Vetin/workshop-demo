## Goal

Implement the checkout form gift wrap UI elements and thread `gift_wrap` / `gift_message`
through five TypeScript layers: form state → CartDetail → Cart.provider → ApiGateway → BFF.

**Prerequisite**: T-01 must complete first (TypeScript stubs regenerated with new fields).

---

## Scope

### 1. New styled component: `GiftMessage.styled.ts`

Create `src/frontend/components/CheckoutForm/GiftMessage.styled.ts`:

```typescript
import styled from 'styled-components';

export const GiftWrapRow = styled.div`
  display: flex;
  align-items: center;
  gap: 8px;
  margin-top: 16px;
`;

export const GiftMessageTextarea = styled.textarea`
  width: 100%;
  min-height: 80px;
  margin-top: 12px;
  padding: 10px 12px;
  border: 1px solid ${({ theme }) => theme.colors.borderGray};
  border-radius: 4px;
  background: ${({ theme }) => theme.colors.backgroundGray};
  font-size: ${({ theme }) => theme.sizes.mMedium};
  color: ${({ theme }) => theme.colors.textGray};
  resize: vertical;
  font-family: inherit;

  &:focus {
    outline: none;
    border-color: ${({ theme }) => theme.colors.otelBlue};
  }
`;
```

**Rules**:
- Use only `Theme` token references. Do NOT use hardcoded hex values (`#f9f9f9`, `#cacaca`,
  etc.) — see `Input.styled.ts` for the anti-pattern to avoid.
- Do NOT use hardcoded `px` for font sizes — use `theme.sizes.*` tokens.
- Theme token names: `otelBlue`, `otelYellow`, `otelGray`, `otelRed`, `backgroundGray`,
  `lightBorderGray`, `borderGray`, `textGray`, `textLightGray`.
- Font size tokens: `theme.sizes.mMedium` = 14px; reference `Checkout.styled.ts`
  for the established pattern.

### 2. Extend `IFormData` in `CheckoutForm.tsx`

`IFormData` is defined and exported from `CheckoutForm.tsx` (imported by `CartDetail.tsx`).
Add the two new fields:

```typescript
export interface IFormData {
  // ... existing fields ...
  gift_wrap: boolean;
  gift_message: string;
}
```

Initialize in the `useState` default value: `gift_wrap: false, gift_message: ''`.

### 3. Update `CheckoutForm.tsx` — add checkbox and textarea

Inside the `<form>` element, after the credit card section:

```tsx
import { GiftWrapRow, GiftMessageTextarea } from './GiftMessage.styled';

{/* Gift Wrap section */}
<GiftWrapRow>
  <input
    type="checkbox"
    id="gift_wrap"
    name="gift_wrap"
    checked={formData.gift_wrap}
    onChange={e => setFormData(prev => ({
      ...prev,
      gift_wrap: e.target.checked,
      gift_message: e.target.checked ? prev.gift_message : '',
    }))}
  />
  <label htmlFor="gift_wrap">Add gift wrap (+$5.00)</label>
</GiftWrapRow>

{formData.gift_wrap && (
  <div>
    <label htmlFor="gift_message">Gift message (optional)</label>
    <GiftMessageTextarea
      id="gift_message"
      name="gift_message"
      maxLength={500}
      value={formData.gift_message}
      onChange={e => setFormData(prev => ({
        ...prev,
        gift_message: e.target.value,
      }))}
      placeholder="Add a personal message..."
    />
  </div>
)}
```

**Accessibility**: both `<label htmlFor>` and matching `id` on the input/textarea must be
present. Note: React uses `htmlFor`, not `for`.

**Conditional mount**: the textarea is conditionally **mounted** (not CSS-hidden). When the
checkbox is unchecked, the textarea is unmounted — clearing the message state.

**Price sync**: the label text `+$5.00` must match the fee value displayed in the CartItems fee
row. Extract the `5.00` amount to a shared constant if possible to prevent drift.

### 4. Update `CartItems.tsx` — gift wrap fee row

In `src/frontend/components/CartItems/CartItems.tsx`, the shipping row uses `<S.DataRow>` with
`<ProductPrice price={shippingConst} />`. Add a gift wrap fee row with the same pattern:

```tsx
// Add giftWrap prop to CartItems props interface:
interface CartItemsProps {
  // ... existing props ...
  giftWrap?: boolean;
}

// Inside the component, alongside the shipping row:
{giftWrap && (
  <S.DataRow>
    <span>Gift Wrap</span>
    <ProductPrice price={{ units: 5, nanos: 0, currencyCode: 'USD' }} />
  </S.DataRow>
)}
```

**Do NOT use `<CheckoutItem>`** — that component requires `checkoutItem: IProductCheckoutItem`
and `address: Address` props (it renders full order-item cards with shipping details). The
correct component for a fee summary row is `S.DataRow` + `ProductPrice`, matching the
shipping row pattern at lines 66–70 of `CartItems.tsx`.

**CartItems total**: The `total` useMemo in `CartItems.tsx` (lines 37–52) sums product costs
and shipping. When `giftWrap=true`, the total displayed will be $5.00 short unless you also
add the gift wrap fee. Update the `total` calculation to add `{ units: 5, nanos: 0 }` when
`giftWrap=true` so the pre-checkout subtotal matches what will be charged.

### 5. Update `CartDetail.tsx` — thread new fields through internal callback

`CartDetail` is a self-contained component with **no props** — it renders `<CheckoutForm
onSubmit={onPlaceOrder} />` where `onPlaceOrder` is a local `useCallback` at line 25.

The threading chain is:
1. `CheckoutForm` submits `IFormData` (now includes `gift_wrap`, `gift_message`) via `onSubmit`
2. `CartDetail.onPlaceOrder` (local `useCallback`) receives the full `IFormData`
3. Calls `placeOrder(...)` from `useCart()` — this is `Cart.provider.placeOrder`
4. `Cart.provider.placeOrder(order: PlaceOrderRequest)` — after T-01, `PlaceOrderRequest`
   has `giftWrap?: boolean` and `giftMessage?: string`
5. `ApiGateway.placeOrder(...)` sends the HTTP POST

Changes needed in `CartDetail.tsx`:
- In the `onPlaceOrder` useCallback body, extract `gift_wrap` and `gift_message` from
  the `formData: IFormData` parameter and pass them to the `placeOrder(...)` call.
- Pass `giftWrap={formData.gift_wrap ?? false}` to `<CartItems>` so the fee row is shown.

Also pass `giftWrap` state down to `<CartItems>` so the fee row reflects the checkbox state.

### 6. Update `ApiGateway.placeOrder` in `src/frontend/gateways/Api.gateway.ts`

The current `placeOrder` function signature is:
```typescript
placeOrder({ currencyCode, ...order }: PlaceOrderRequest & { currencyCode: string })
```

It passes `body: order` (a spread of all `PlaceOrderRequest` fields) to the `request()`
utility. After T-01 regenerates `PlaceOrderRequest` to include `giftWrap?: boolean` and
`giftMessage?: string`, those fields will automatically be included in `body: order` via the
rest spread. **No explicit code change is needed in `Api.gateway.ts`** if the TypeScript
types are updated by T-01 regeneration.

Verify that the resulting HTTP POST body includes the new fields by checking that `PlaceOrderRequest`
in `protos/demo.ts` has the new fields after T-01.

### 7. Update BFF `src/frontend/pages/api/checkout.ts`

The current handler casts the entire body as `PlaceOrderRequest`:
```typescript
const orderData = body as PlaceOrderRequest;
```

After T-01 adds `giftWrap?: boolean` and `giftMessage?: string` to `PlaceOrderRequest`,
the existing cast will automatically carry the new fields. The existing `CheckoutGateway.placeOrder(orderData)` call passes `orderData` directly to gRPC, so no additional field extraction is needed.

**Important**: proto-generated TypeScript types use camelCase (`giftWrap`, `giftMessage`).
The browser POST body uses these same camelCase names (set by `ApiGateway.placeOrder` which
uses the generated TypeScript types). No snake_case to camelCase mapping is needed in the BFF.

**Security note**: `gift_message` passes through the BFF as part of the request body. Do NOT add
`console.log(orderData)` or any request-body logging in this file. Next.js does not log request
bodies by default; do not change that behavior.
