## OTel Instrumentation Patterns (Kotlin / JVM)

### Java Agent Auto-Instrumentation

fraud-detection runs on the JVM with the OpenTelemetry Java agent:

```
JAVA_TOOL_OPTIONS=-javaagent:/usr/share/java/opentelemetry-javaagent.jar
```

The agent automatically instruments:
- Kafka Streams processing (consumer/producer operations)
- HTTP clients (if used)
- Logging frameworks (injects trace context into log records)

**Never remove or alter `JAVA_TOOL_OPTIONS`.**

### Kafka Experimental Span Attributes

The following env var is set to enable richer Kafka span attributes:

```
OTEL_INSTRUMENTATION_KAFKA_EXPERIMENTAL_SPAN_ATTRIBUTES=true
```

This adds topic, partition, and offset attributes to Kafka spans. Do not remove this setting — it is intentional for demo observability purposes.

### Manual Spans (Kotlin syntax)

```kotlin
import io.opentelemetry.api.GlobalOpenTelemetry
import io.opentelemetry.api.trace.StatusCode

val tracer = GlobalOpenTelemetry.getTracer("fraud-detection")
val span = tracer.spanBuilder("DetectFraud").startSpan()
span.makeCurrent().use {
    span.setAttribute("order.id", orderId)
    try {
        // detection logic
    } catch (e: Exception) {
        span.recordException(e)
        span.setStatus(StatusCode.ERROR, e.message ?: "error")
    } finally {
        span.end()
    }
}
```

### OTLP HTTP Exporter

Configured via environment variables (do not hardcode):

```
OTEL_EXPORTER_OTLP_ENDPOINT=http://otelcol:4318
OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
```

### Protobuf

Stubs are generated by the Gradle protobuf plugin. Do not hand-edit generated files under `build/generated/`.

## Rules

1. **Preserve all OTel instrumentation.** Never remove `JAVA_TOOL_OPTIONS`, `OTEL_INSTRUMENTATION_KAFKA_EXPERIMENTAL_SPAN_ATTRIBUTES`, or manual tracer/meter usage.
2. **Never hide telemetry-impacting changes.** If your change affects what spans, metrics, or logs are emitted, state this explicitly in your output.
3. **Cite every changed file** in your output (absolute path).
4. **Run lint/build after changes:**
   - `./gradlew build` from `src/fraud-detection/`
   - `./gradlew test` for unit tests
5. **Do not hand-edit generated protobuf Kotlin/Java files** under `build/generated/`.
6. The fraud-detection service consumes from the same Kafka topics used by accounting — changes to message formats affect both services.

## Common Pitfalls

- Kafka Streams topology changes can affect consumer group offsets — document any topology changes clearly.
- The Java agent must not be overridden by `OpenTelemetrySdk.builder()` in application code — use `GlobalOpenTelemetry` for any manual instrumentation.
- `OTEL_SERVICE_NAME` and `OTEL_RESOURCE_ATTRIBUTES` come from docker-compose / K8s env — do not hardcode.
- Kafka experimental attributes (`OTEL_INSTRUMENTATION_KAFKA_EXPERIMENTAL_SPAN_ATTRIBUTES=true`) are intentional and required for the demo's dashboards — do not disable.
