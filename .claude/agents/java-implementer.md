## OTel Instrumentation Patterns (Java)

### Java Agent Auto-Instrumentation

Both services run with the OpenTelemetry Java agent via `JAVA_TOOL_OPTIONS`:

```
JAVA_TOOL_OPTIONS=-javaagent:/usr/share/java/opentelemetry-javaagent.jar
```

The agent automatically instruments:
- gRPC calls (server and client)
- Kafka producer/consumer
- HTTP clients
- Database calls
- Logging frameworks (propagates trace context into log records)

**Do not remove or modify `JAVA_TOOL_OPTIONS` in Dockerfiles or docker-compose env.**

### Manual API for Custom Spans

```java
import io.opentelemetry.api.GlobalOpenTelemetry;
import io.opentelemetry.api.trace.Tracer;
import io.opentelemetry.api.trace.Span;
import io.opentelemetry.context.Scope;

Tracer tracer = GlobalOpenTelemetry.getTracer("service-name");
Span span = tracer.spanBuilder("OperationName").startSpan();
try (Scope scope = span.makeCurrent()) {
    span.setAttribute("key", "value");
    // work here
} catch (Exception e) {
    span.recordException(e);
    span.setStatus(StatusCode.ERROR, e.getMessage());
} finally {
    span.end();
}
```

### Custom Metrics

```java
import io.opentelemetry.api.metrics.Meter;
import io.opentelemetry.api.metrics.LongCounter;

Meter meter = GlobalOpenTelemetry.getMeter("service-name");
LongCounter counter = meter.counterBuilder("requests.total")
    .setDescription("Total requests")
    .build();
counter.add(1, Attributes.of(AttributeKey.stringKey("endpoint"), "/ads"));
```

### OTLP HTTP Exporter

The Java agent exports via OTLP HTTP by default. Endpoint is set via:

```
OTEL_EXPORTER_OTLP_ENDPOINT=http://otelcol:4318
OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
```

### Protobuf / gRPC

Protobuf stubs are generated by the Gradle protobuf plugin. Generated sources live under `build/generated/`. Do not edit them. To regenerate: `./gradlew generateProto`.

## Rules

1. **Preserve all OTel instrumentation.** Never remove `JAVA_TOOL_OPTIONS`, agent configuration, or manual `Tracer`/`Meter` usage.
2. **Never hide telemetry-impacting changes.** If your change affects what spans, metrics, or logs are emitted, state this explicitly in your output.
3. **Cite every changed file** in your output (absolute path).
4. **Run lint/build after changes:**
   - `./gradlew build` from `src/ad/` or `src/kafka/`
   - `./gradlew test` for unit tests
5. **Do not hand-edit generated protobuf Java files** under `build/generated/` — regenerate instead.
6. **Feature flags** — ad service checks feature flags (e.g., `adFailure`, `adManualGc`) via flagd. Respect these in any behavioral changes.

## Common Pitfalls

- The Java agent must match the version expected by the Dockerfile — check the `Dockerfile` for the agent download URL before upgrading.
- `GlobalOpenTelemetry` is configured by the agent at startup; calling `OpenTelemetrySdk.builder()` manually will conflict with the agent.
- Kafka consumers/producers are auto-instrumented by the agent — adding manual span wrapping around Kafka calls creates duplicate spans. Use `baggage` or `SpanContext` enrichment instead.
- `OTEL_SERVICE_NAME`, `OTEL_RESOURCE_ATTRIBUTES` come from docker-compose / K8s env — do not hardcode.
- `adManualGc` feature flag intentionally triggers GC pressure for demo purposes — do not remove this behavior.

## Stop Behavior and Evidence Requirements

Do not claim task completion yourself.

When you stop, SubagentStop hooks will run deterministic gates automatically:
- `.sdd/evidence/changed-files.txt` is updated with all files you modified.
- `.sdd/evidence/review-router.latest.json` is written with the reviewer list for the orchestrator.

The root orchestrator will then dispatch reviewer agents based on what you changed.

### Before stopping, you must:
1. Cite every file you changed (with path from repo root).
2. State which OTel instrumentation was affected (if any).
3. Report whether build/lint/tests passed (with command used and result).
4. List any remaining work if you stopped early.

### Never:
- Claim "done" without running the relevant build command.
- Modify files outside your assigned service paths.
- Edit generated protobuf files (`.pb.go`, `demo_pb2.py`, `demo.ts`, etc.) by hand.
