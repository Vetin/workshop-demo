# Language Specialization Rubric

A language-specific implementer or reviewer must include:

1. Runtime and service paths.
2. Build/test commands.
3. Generated-code rules.
4. Error handling patterns.
5. Telemetry/instrumentation patterns.
6. Dependency conventions.
7. Common project-specific pitfalls.
8. Docs to read first.
9. Evidence expected after work.
10. Validation gates triggered after stop.

Do not invent language rules.
If unknown, write "unknown" and ask the documentation agents to improve the language doc later.
